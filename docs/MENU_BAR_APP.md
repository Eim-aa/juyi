# 句译原生 macOS App

句译是 **macOS 15+ 公开测试版**，不是稳定版。App 原生负责 Apple 路径的双 Option 监听、辅助功能取词、端上翻译和译文浮窗。build 12 起，全新本地安装不需要 Hammerspoon；仅已有早期开发组件时通过既有 owner 协议交接。用户目标是在支持的 App 选中英文，连按两次 Option（⌥⌥）查看简体中文。

## 安装

**本地翻译：** 从 [GitHub Releases](https://github.com/Eim-aa/juyi/releases) 下载标明已签名、公证的最新 DMG，无需登录 GitHub。将句译拖到“应用程序”后打开，按照 [安装与第一次翻译](INSTALL.html) 完成授权和语言资源准备。build 11 仍需 Hammerspoon，独立原生安装从 build 12 开始；请核对发布说明。

以下是**可选云端／早期兼容组件的完整源码安装**，不属于普通本地用户的安装步骤。它要求 Homebrew、Python ≥ 3.10 和 Xcode/Command Line Tools。`scripts/install.sh` 会准备后台、Hammerspoon 并安装 App：

```bash
git clone https://github.com/Eim-aa/juyi.git ~/.local/share/argos-translator
~/.local/share/argos-translator/scripts/install.sh
```

只重新构建和安装原生 App（不会安装完整依赖）：

```bash
~/.local/share/argos-translator/scripts/install_macos_app.sh
```

**源码安装依赖与运行依赖不同。** build 12 起的全新 Apple 本地安装只需要句译、辅助功能权限和系统中英语言包，不需要 Python、FastAPI、独立 translation helper 或 Hammerspoon。检测到早期开发配置或运行中的 Hammerspoon 时，仍需完成安全交接；不会把过期状态当成安全证明。

安装脚本会先构建并校验版本与 ad-hoc 签名，再更新系统“应用程序”中的 App；此签名检查不能替代 Developer ID 与公证。需要时 macOS 会显示管理员授权窗口。新 App 验证成功后才把旧的个人“应用程序”副本移到废纸篓。用户的引擎选择和钥匙串中的火山密钥不会被删除。脚本不覆盖自定义的同名 Hammerspoon 模块；冲突时停止并给出提示。

## 第一次使用

安装后直接从“应用程序”打开“句译”（`/Applications/句译.app`），不需要终端。首次启动会出现一个可跳过、可继续的两步教学：

1. **启用原生双 Option**：按界面提示在“系统设置 → 隐私与安全性 → 辅助功能”为 **句译** 开启权限，回到 App 后会复检。此权限必须由用户本人授予。仅已有早期开发组件时，才会更新 Hammerspoon 交接模块并观察其安全让出；全新本地安装跳过这一步。已有火山云端密钥不会被删除。
2. **实际试用**：点击“打开文本编辑”，新建文稿，输入并选中 `Good tools should feel effortless.`，再快速连按两次 Option。看到原生译文浮窗后回到句译点“我看到了译文”。句译自身窗口不会被当作取词目标。需要语言包时在句译点击“准备 Apple 语言包”，按 macOS 提示确认。

每一步都可以点“稍后再说”。这不会被误记为完成；主界面和菜单栏会保留“继续设置”入口。完成后可以从主界面的“重新学习”直接再练一次快捷键，也可以在“诊断与帮助”中完整重新运行设置。重新运行不会清除引擎选择或云端密钥。

如果窗口被关闭，句译仍会留在 Dock 和菜单栏；点击 Dock 图标或菜单栏中的句译图标即可重新打开唯一的控制窗口，也可以以后从 Launchpad 或系统“应用程序”再次打开。首次教学只有在用户明确确认看到了译文后才算完成。

Apple 模式的首页状态、图标和快捷键就绪判断以原生 coordinator 为准；原生启用必须经过句译辅助功能、语言包和 owner 交接检查。Python 服务或旧监听在线不代表原生 Apple 已就绪。

## 支持范围与隐私

先在文本编辑中验证最短路径，再尝试自己的常用 App。其他 App 和带文本层 PDF 的选区能否读取，取决于其辅助功能接口；扫描图片 PDF、安全输入框与受保护内容不支持。代码中具备某种读取路径不等于已验证所有应用版本，具体候选包验收见 [产品审查记录](PRODUCT_REVIEW_2026-09-22.md)。

WPS PDF 不提供可用选区接口时，兼容取词可能临时执行系统复制，并尽力恢复原剪贴板。剪贴板管理器可能保留原文或干扰取词；敏感内容请避免使用这条路径。首次练习前及主页保留简短提醒，详细说明放在“诊断与帮助 → 支持范围与隐私”。Apple 翻译本身在本机处理正文，语言资源由系统下载；Apple 失败不会自动上传云端。

## 翻译方式

- **Apple 离线**：默认选项；文本只在本机处理，需要 macOS 15+ 和系统中英语言包。
- **火山云端**：次级、可选联网模式，仍需额外的 Python 后台和用户自行配置密钥。入口位于“其他翻译方式与已有设置”和菜单栏；已有配置不会因首页简化而删除。选中文本会发送至火山翻译，是否更适合应以自己的固定语料对比。

火山密钥有常驻字段标签、显隐控制和真实翻译验证。候选密钥先保存到独立的 pending 钥匙串项，验证成功后才替换正式凭据；pending 标记会保留到服务重启和正式凭据实测均成功，意外中断时下次启动会前向完成或安全清理。验证失败时不会覆盖旧配置。移除云端配置也使用持久事务标记；标记存在或无法验证时，Hammerspoon 与本地服务都会逐请求阻止云端翻译。密钥不写入源码、仓库、HTTP 请求正文或运行日志。旧版 `volc.env` 中的 AK/SK 会安全迁移到钥匙串。Apple 离线不可用时不会静默回退云端。

可选云端/兼容功能调用本地服务时携带安装阶段生成的随机令牌。令牌只对当前用户可读，用于阻止浏览器页面或无权读取令牌的本机客户端调用翻译与密钥验证接口。原生 Apple 划词翻译不经过该服务。

## 菜单栏

原生句译是唯一的句译菜单入口，提供当前状态、打开窗口、切换引擎、暂停/恢复和诊断。在 Apple 原生链中，句译处理双 Option、AX 取词和译文浮窗；Hammerspoon 不再处理这些动作，只按 owner 协议让出旧链，也不创建第二个句译菜单。

关闭窗口继续翻译；“暂停句译”停止翻译，保留控制界面；“退出句译”先持久保存共享暂停状态，再停用原生链并退出，旧兼容链也保持暂停。退出后重开需点击“恢复句译”，教学中重开也提供恢复入口。Hammerspoon 或可选后台进程仍可能运行，但不表示句译快捷键仍应取词；句译不退出用户的其他 Hammerspoon 功能。

“测试翻译引擎”位于“诊断与帮助”中。Apple 自测直接运行原生 Translation framework 的固定样例，不调用 Python；云端测试走现有后台。该测试只证明引擎能翻译，不能代替新手教学里的真实选区与双 Option 试用。原生语言包准备与恢复也不以重启 Python 为修复动作。

译文浮窗支持点击复制完整译文、按 Escape 关闭和点击外部关闭。长译文在屏幕内安全截断展示，复制时仍会得到完整内容；连续触发时，旧请求的定时器或迟到响应不会覆盖较新的译文。

Dock 与菜单栏会同时保留句译入口。关闭窗口只关闭控制窗口，不会退出句译、停止后台翻译组件或移除双 Option 快捷键；从 Dock、Finder、Launchpad 或菜单栏再次打开时，会前置同一个窗口。

## 登录时自动打开

首次打开时，句译会尝试把自己注册为登录项，让 Dock 与菜单栏入口在下次登录后自动出现。这个设置独立于翻译服务，即使注册失败也不会阻止当前翻译。

可在“诊断与帮助”中开关“登录时自动打开句译”。界面会区分已开启、未开启、需要系统确认和 App 路径不可用；需要用户确认时，可直接打开“系统设置 → 通用 → 登录项”。

登录启动不会自动弹出控制窗口，但 Dock 与菜单栏入口都会出现。源码的 ad-hoc 本地构建在系统登录项 API 不可用时，会自动使用当前用户的兼容登录设置；正式 Developer ID 构建继续使用 macOS 的 ServiceManagement。两种路径共用同一个界面开关，用户不需要了解内部差异。

## 开发与发布

```bash
xcodebuild -project Juyi.xcodeproj -scheme Juyi \
  -configuration Debug -derivedDataPath /tmp/JuyiDebug build
open /tmp/JuyiDebug/Build/Products/Debug/Juyi.app
```

正式工程构建 App 与 Apple Translation helper，二者都是 Universal 2（Apple Silicon + Intel），最低支持 macOS 15.0。现有 `scripts/build_macos_app.sh` 仍可用于安装脚本兼容路径，并读取与 Xcode 相同的版本和 deployment target。本地源码构建使用 ad-hoc 签名；公开下载版本在发布前仍必须配置 Developer ID 签名与 Apple 公证。完整构建契约见 [RELEASE_BASELINE.md](RELEASE_BASELINE.md)。

当前原生 App 已承载 Apple 主链，并保留既有开发组件的 owner 互斥。每次公开新版都必须重新签名、公证、验证下载包；源码构建不自动获得发行信任。干净账户和不同硬件上的真实端到端验收仍须单独记录。可选云端需要独立后台，不能把这个要求泛化成 Apple 模式必须安装 Python。

当前 Apple-only MVP 刻意不扩展新翻译供应商、多语言、OCR 或翻译历史。Python 后端继续服务可选云端和兼容路径；Hammerspoon 只保留旧链兼容与 owner 交接职责。
