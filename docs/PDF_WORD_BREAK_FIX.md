# PDF 断词修复 · build 11

## 用户可用变化

已接入原生选区读取链。文档元数据确认是 PDF，且读前、读后文档及进程身份一致时，翻译前修复英文排版断词。

- 预览：`ob-` 换行 `served` → `observed`，`work-` 换行 `force` → `workforce`。
- WPS：单词中间的 U+FFFE、U+0002、软连字符按同一规则处理。
- 使用本机英语拼写服务确认拼接后的单词；未知拼接保留连字符，移除相关的布局换行或异常字符。
- 保留普通文本、内联硬连字符、段落间空行和列表；对 `re-sign` 等可能改变意思的前缀保守保留连字符。
- 不新增 OCR、云端调用、剪贴板路径、Lab、编译条件或 owner 协议。现有 WPS 复制恢复及失效检查不放宽。

## 已验证

真实样本来自用户 Ramp/Revelio PDF 第一页摘要。同一句的预览原文、WPS 纯文本，经过实际生产修复函数后得到相同输入。分别送入项目已有 Apple Translation helper，得到相同中文译文，`observed` 和 `workforce` 的断词误译消失。

完整选区读取回归通过，覆盖普通文本不变、真实连字符、段落边界及权限/焦点失效。Release 已构建 Universal 2，并通过二进制、签名和 Hardened Runtime 检查。当前仍为 ad-hoc 本地预览签名，不是已公证分发。

2026-09-25：用户在已安装的 `/Applications/句译.app`（0.4.0 build 11）实际复测后确认行尾断词问题已解决。这是本机真实使用验收，不代表所有 PDF、阅读器或硬件均已覆盖。

## 尚未验证及限制

- 新账户首次安装、macOS 15 和 Intel 真机尚未验收；不能用本机已有权限的复测代替。
- 英语词典不是完整排版分析：专有名词、罕见词、跨栏文本或歧义复合词仍可能需要更进一步处理。未把所有换行全部替换为空格。
- 原本译文中的冗余仍可能存在，修复输入不保证翻译引擎的全部语义质量。
- README 视频来自 build 10，仅演示标题翻译，不宣称展示本次断词修复。

安装回滚使用本次更新前的 build 10 ZIP 备份；不修改原 PDF 或原录屏。`scripts/start_service.command` 未读取、修改或执行。
