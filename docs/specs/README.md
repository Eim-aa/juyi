每份可独立评审、独立交付；本页说明优先级与依赖关系。

| # | Spec | 一句话 | 工作量 | 依赖 |
| - | ---- | ------ | ------ | ---- |
| 1 | [菜单栏控制中心与首次运行向导](01-menubar-control-center.md) | 把菜单栏变成状态/配置/引导入口，消灭配置终端步骤 | ~4–6 人日 | 建议在 #3 之后 |
| 2 | [安装门槛降低](02-install-friction.md) | 预编译 helper、双击安装入口、去 git/CLT 依赖 | ~2–3 人日 | **依赖 #5**（Release 产物） |
| 3 | [错误可见性与健壮性修复](03-error-visibility-robustness.md) ✅ 已实现 | 引擎错误不再被静默吞掉 + 一批健壮性小修 | ~2–3 人日 | 无 |
| 4 | [Argos 残留清理](04-argos-cleanup.md) ✅ 已实现 | 死配置、legacy 字段、plist 残留、uninstall.sh 重写 | ~1–2 人日 | 无 |
| 5 | [CI 与发布流水线](05-ci-release.md) | GitHub Actions 检查 + helper 自动构建发布 | ~2 人日 | 无 |

## 建议实施顺序

```
第 1 批（修正确性，小而快）：  #3 + #4        —— 可合并成一个里程碑
第 2 批（基建）：              #5             —— 与第 1 批可并行
第 3 批（体验）：              #1             —— 独立，随时可插队
第 4 批（分发）：              #2             —— 等 #5 的 Release 产物就绪
```

## 共同的非目标（所有 spec 均不包含）

- **原生 SwiftUI app 重写**（此前评审的"第三档"）：战略决策未定
  （是否进入 Easydict/Bob 的消费级赛道），任何 spec 不得为其提前
  引入架构承诺；但也不做阻碍它的决定。
- **多语言对支持**：产品定位保持"仅英→中"（见根 README）。
- **OCR / 历史记录 / 生词本**：超出"划词即译"定位。

## 共用人物设定（User Story 中引用）

- **开发者用户**：现有核心受众，会用终端，通过 README/AGENTS.md 安装。
- **非技术用户**：想要划词翻译，不开终端，遇到报错即放弃。
- **AI Agent**：按 AGENTS.md 代人部署的 Claude Code 等（本项目的特色安装路径）。
- **维护者/贡献者**：改代码、审 PR、发版本的人（基建类 spec 的主要用户）。
